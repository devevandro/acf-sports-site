## CI/CD

GitHub Actions workflows in `.github/workflows/` deploy to Vercel via the Vercel CLI: `prev-deploy.yaml` runs on push to `stage` (preview environment), `prod-deploy.yaml` runs on push to `main` (production environment). Both require `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`, and `VERCEL_TOKEN` secrets configured in the `Deploy` GitHub environment. `prev-deploy.yaml`'s `vercel build`/`vercel deploy` steps take no `--preview` flag — Vercel CLI 59.x rejects it (`unknown or unexpected option: --preview`); preview is simply the default target when `--prod` is omitted.

The `acf-site` Vercel project has no Git repository connected (created via CLI), so the Vercel dashboard cannot list branches for domain assignment. `prev-deploy.yaml` works around this by capturing the deployment URL from `vercel deploy --prebuilt` and running `vercel alias set <url> stage.acfsports.com.br` right after, giving `stage` a fixed preview domain without needing Git integration. `prod-deploy.yaml` doesn't need this step because `acfsports.com.br` is assigned to the Production target and Vercel auto-aliases it on every `--prod` deploy. The `stage.acfsports.com.br` DNS record (CNAME to `cname.vercel-dns.com`) must be created in Cloudflare for the alias to resolve.

The project's SSO deployment protection (`vercel project protection`) is set to `all_except_custom_domains`, which only exempts domains formally registered on the project (`vercel domains add`), not bare aliases (`vercel alias set`). `stage.acfsports.com.br` was registered as a project domain via `vercel domains add stage.acfsports.com.br acf-site` so it resolves publicly without a Vercel login prompt, same as `acfsports.com.br`.

## Recent Changes (Fixed-Width Rows Overflowing Between 1200px–1480px Viewports)

Safe because the card is an inline `<svg viewBox="0 0 256 448">` — its internal `<path>`/`<image>` scale proportionally with the element's rendered size, so shrinking it introduces no distortion. The existing `≤1200px` breakpoint (horizontally scrollable tier) already resets both `width`/`height` back to fixed `256/448`, so it's unaffected.
  - `.components-news-grid-grid` (Home "notícias", 3 × `330px` + 2 × `40px` gap = `1070px`, needed inside a column whose max is itself derived from the same `1440px` container): `grid-template-columns` changed from `repeat(var(--news-grid-columns, 3), 330px)` to `repeat(var(--news-grid-columns, 3), min(330px, calc((100% - (var(--news-grid-columns, 3) - 1) * 40px) / var(--news-grid-columns, 3))))`, and `.components-news-grid-card`/`.components-news-grid-cardImage` (+ the unused `layeredImage`/`mascotImage` variants) changed from `width: 330px` to `width: 100%` to fill the now-fluid track.
  - `.components-roster-roster-page-content-grid` (`/clube/elenco` full listing, 5 × `256px` + 4 × `40px` = `1440px`): **not** shrunk like the above two — its card (`.components-roster-athlete-card-card`) uses a CSS `clip-path: path(...)` with hardcoded absolute-pixel coordinates on a plain HTML element, which does not scale when the box is resized (unlike an SVG `viewBox`), so shrinking it would visibly distort the hexagon notch shape. Fixed via breakpoints instead: added a `@media (max-width: 1480px)` tier dropping to `repeat(4, 256px)` (`4 × 256 + 3 × 40 = 1144px`, safe down to ~`1184px` viewport). This also fixed a **pre-existing, unrelated dead-CSS bug**: two separate `@media (max-width: 1200px)` blocks both redefined this grid's `grid-template-columns` (`repeat(4, 256px)` then, immediately after in source order, `repeat(3, 256px)`) — same specificity, same condition, so the first was always silently overridden and never actually rendered. Removed the now-redundant duplicate.
  - `.components-main-menu-menu` header padding's floor (`max(24px, ...)`) didn't match the content containers' floor (`min(1440px, calc(100% - 40px))` degenerates to a flat `20px`), so below `1480px` the header sat 4px further in than every section below it. Changed the header's floor from `24px` to `20px` so both formulas produce the exact same inset at every viewport width, not just above `1480px`.
